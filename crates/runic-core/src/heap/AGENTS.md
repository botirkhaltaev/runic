# AGENTS.md

Scope: `crates/runic-core/src/heap/`. `run/` and `extent/` have their own.

- Flat layout: `mod.rs` (`Heap` / `HeapInner` / `AllocatorCtx`), `heaps.rs`, `state.rs`, `list.rs`, `queue/`, `inbox.rs`, `thread.rs`, plus `run/` / `extent/`.
- `Heaps`: `Arena<Heap>`; `get` is lock-free `Arena` then `Heap::matches` (slot + generation). Free heaps are an `Mpmc` stack. Owner give-up is `unbind` (close Active, wait leases, flush/accept/reclaim). Draining API: `free` / `flush` (`owner: Option`. `Some` uses `owner.heap()`, `None` `get`s). Fail when the OS will not map or the arena is full.
- Exclusive metadata is `Mutex<HeapInner>`. One guard at a time, for the heap whose available runs or extent cache is changing. Active `flush_owner` accepts outside the lock and `require_inner` lists or caches one node (`push_available` / `cache_or_unmap`). Alloc walks every attached heap: flush and take a run or cached extent it already holds (one guard at a time), then map on the first heap that can. No heap is the only mapper. `Heap::adopt` CASes Draining to Active first; only the winner locks, and it keeps that guard through its flush, so a losing adopter never touches the mutex. `Inbox::flush` drains until empty. `accept_run` enqueues the run again when a push landed after the swap; `accept_extent` does not. Both take the guard source as a closure so Active and Draining share one accept body. Draining: `Heaps::admit` / `Heap::admit` then `flush` under one guard through reclaim (`owner` enqueues a claim before accept). `AllocatorCtx` is the parent bag, not a lock guard. `ThreadHeaps::unbind` pops the list. Bind links at the front. Adopt links at the back. `take_idle` uses `Heap::is_idle` and unlinks one idle heap only while another remains.
- `THREAD_HEAPS` is `#[thread_local]` `!Drop` ELF TLS. Default builds use `UnbindGuard`; `c-abi` builds use `UnbindHook`, a once-per-thread `pthread` key because Rust TLS destructor registration allocates and re-enters `bind` under `LD_PRELOAD`.
